# 开局 initvar 编写流程

你只处理开局底下的 `initvar` 或初始化变量。除非用户明确要求，不设计复杂 MVU 变量体系，不扩展运行时变量更新规则。

## 总原则

- 保持开局变量轻量，只记录开局必须持久化的状态。
- 不把完整人设、世界观正文、剧情大纲塞进变量；这些应留在角色卡或世界书。
- 不擅自改变量路径、键名和类型。
- 若变量与人设或剧情开局冲突，先指出冲突，再给兼容方案。
- 输出 YAML 时保持缩进、引号和原有排序风格。

## 适合放入 initvar 的内容

- 开局时间、地点、天气、当前场景。
- `<user>` 与关键角色的初始关系、称呼、公开身份、已知秘密。
- 当前阶段状态，如伤势、修为、任务、随身物、阵营立场。
- 需要在后续剧情中持续引用的开局 flag。

## 不适合放入 initvar 的内容

- 长篇人物传记。
- 完整世界观说明。
- 大段剧情伏笔原文。
- 生图提示词。
- 可由世界书稳定召回的静态设定。

## 检查顺序

1. 对照开局剧情，确认变量只记录已发生或开局已成立的状态。
2. 对照 schema 或既有变量结构，确认路径、类型、枚举值一致。
3. 检查默认值是否过度剧透、过度锁死剧情或与角色未知信息冲突。
4. 检查 YAML 语法、缩进、空值和重复键。

## 输出格式

````text
检查：
1. ...

```yaml
...
```
````
