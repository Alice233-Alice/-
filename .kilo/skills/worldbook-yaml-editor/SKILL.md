# 世界书 YAML 编辑流程

你用于处理 SillyTavern 世界书、阶段人设、世界观条目、剧情条目和开局 initvar。目标是保持结构稳定、触发可靠、设定不丢失。

## 总原则

- 不擅自改键名、删字段、改目录语义、合并条目或移动内容。
- 优先保留用户已有条目、触发词、注释、排序和缩进风格。
- 修复 YAML 时只改必要语法，避免顺手重写文本。
- 扩写设定时新增内容应贴合原条目，不覆盖原设。
- 对大改动先说明“将保留什么、将调整什么、为什么调整”。

## YAML 检查顺序

1. 检查缩进、冒号、引号、数组、块文本 `|-` 或 `>` 是否有效。
2. 检查同名键、重复条目、空值、不可见字符和编码异常。
3. 检查触发词是否过宽、过窄、互相抢占或缺少角色别称。
4. 检查阶段人设是否与基础人设、前后阶段、世界观时间线冲突。
5. 检查条目长度是否过载，是否可拆成基础设定、关系设定、阶段设定、行为规则。
6. 检查是否适合长期对话调用：信息密度足够，触发后不会压垮上下文。
7. 检查剧情条目是否能推动事件、关系和选择，而非只堆背景说明。

## 世界书条目写法

- 基础条目写稳定事实，少写临场情绪。
- 阶段条目写当前阶段的新增关系、限制、行为倾向、剧情钩子。
- 触发词包含姓名、别称、身份称谓和关键地点；避免只有通用词。
- 不把所有人物信息塞进一个超长条目；按“人物 / 关系 / 地点 / 事件 / 阶段”拆分。
- 对角色说话风格、行动边界、长期目标可单独成条，便于稳定调用。

## 变量与 initvar

本项目的 Kilo 工作重点是生图提示词、人设、世界观与剧情。除开局底下的 `initvar` 外，不主动处理变量，不把普通写作任务扩展成 MVU 变量工程。

只有当用户明确提到开局 `initvar`、初始化变量、schema 或变量初始值时：

- 先寻找同目录或项目中的 `schema.ts`、`schema.json`、`initvar.yaml`、世界书变量条目。
- 保持变量路径与 schema 一致，不凭空改名。
- 对固定字段、动态字段和只读字段分开处理。
- 不列出自解释且无特殊规则的变量，避免浪费 token。
- 初始化内容应只承载开局必要状态，不把剧情、人设和世界观正文塞进变量。

## 输出格式

修复 YAML 时给出完整修复片段，并简要列出改动：

````text
改动：
1. ...

修复稿：
```yaml
...
```
````

若用户要求只检查，先不改正文，只列问题和建议。
