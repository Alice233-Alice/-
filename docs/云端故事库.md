# 云端故事库初版

测试版“寻途与行旅”内提供“随心寻途”和“云端故事”。玩家选篇后，故事版本和完整蓝图保存到当前行旅，已有存档在断网、云端改稿和故事下架后继续承接。

## 作者发布

故事源统一配置在 src/灯火通明-测试版/cloud-stories.ts，默认读取公开仓库 Alice233-Alice/denghuo-stories 的 main 分支及 library.json。

1. 建立该公开仓库，以 main 作为默认分支。
2. 在 GitHub 创建细粒度个人访问令牌，仅选中故事仓库，授予 Contents 读写权限。
3. 打开“云端故事”的“故事管理”，临时填入凭证并点击“载入云端版本”。
4. 填写名称、题材、篇幅、简介、所求和入手方式。导入 Markdown 或 TXT 幕后文稿，或直接编辑蓝图。
5. 预览玩家可见资料后发布。发布成功后可查看 GitHub 提交，公开读取地址的缓存更新可能稍有延迟。

管理窗口关闭、切换寻途方式或页面卸载时，凭证从内存清除。凭证只需在管理窗口填写，玩家读取故事无需凭证。

发布冲突时，编辑内容继续保留。重新载入云端版本后，先核对下方最新文稿，再发布自己的修改。下架只移除共享目录中的故事，已开始的行旅仍保留原版本。

## 文稿与示例

examples/cloud-stories/无灯客栈.md 提供一篇恐怖支线的幕后文稿，包含四个节点和两种收束；同目录 sample.json 保存展示资料。

运行 node
tools/prepare-cloud-stories.cjs，会生成供新仓库首次初始化使用的 output/cloud-stories/library.json。此样例通过相同的故事格式校验，前端正常运行时从云端读取文稿。日常新增和改稿通过“故事管理”合并到现有故事库。

作者固定真相、人物动机、节点因果及收束条件。正文 AI 随实际行动演绎，手札记录已发生事实，实际叙事遵循程度通过试玩核对。

## 文件约定

library.json 顶层包含 formatVersion:
1 和 stories 数组。每篇包含 id、revision、name、genres、length、lead、goal、step、blueprint。稳定 ID 用于识别同篇故事，修订版本由管理界面递增。

完整文件按 UTF-8 字节计算，最多 1,000,000 字节。大小或格式检查失败时保留编辑内容。

仓库中的完整文稿对外公开。普通玩家界面只展示简介和行动入口，幕后内容仅在作者管理界面及 AI 剧情上下文使用。初版采用纯文本导入，文稿内容作为剧情素材处理。
